PROJECT OVERVIEW
================================================================================
Farmify is an intelligent agricultural platform that combines Machine Learning and 
Deep Learning to help farmers make data-driven decisions. It addresses three core 
challenges in modern agriculture:
  1. Inefficient crop selection
  2. Soil degradation
  3. Crop losses due to diseases

The platform provides a user-friendly web interface enabling farmers to:
  - Receive tailored crop recommendations based on soil and climate conditions
  - Detect plant diseases through image analysis
  - Get agricultural advice through an AI-powered chatbot


KEY FEATURES
================================================================================

1. CROP RECOMMENDATION SYSTEM
   - Farmers input soil parameters: Nitrogen (N), Phosphorus (P), Potassium (K), pH
   - Climate data input: Temperature, Humidity, Rainfall
   - Machine Learning model analyzes inputs
   - System recommends most suitable crop with probability of success
   - Performance: 95-98% accuracy on training and test datasets
   
2. PLANT DISEASE DETECTION
   - Farmers upload images of crops/leaves showing disease symptoms
   - CNN (Convolutional Neural Network) analyzes images
   - System identifies diseases and provides treatment suggestions
   - Enables early intervention and prevents crop loss
   - Performance: 90-95% accuracy on training and test datasets
   
3. AI-POWERED CHATBOT
   - Natural language support for agricultural queries
   - Built using Retrieval-Augmented Generation (RAG)
   - Integrated with HuggingFace API
   - Can analyze uploaded images using YOLOv8 for disease detection
   - Provides context-aware, scientifically-backed responses
   
4. SPECIAL CAPABILITIES
   - Region-specific & real-time recommendations
   - Dynamic adaptation to user-supplied and real-time weather data
   - User-friendly web interface for all digital literacy levels
   - Continuous model improvement through user feedback
   - Mobile and IoT-ready architecture
   - Secure data handling and privacy protection

MACHINE LEARNING MODELS
================================================================================

MODEL 1: CROP RECOMMENDATION (Random Forest Classifier)
─────────────────────────────────────────────────────────
Location: random_forest_model.pkl
Algorithm: Random Forest Classifier
Framework: scikit-learn
Training Process:
  1. Data Loading: 2,200+ agricultural samples from CSV
  2. Feature Extraction: 7 features extracted from dataset
  3. Label Encoding: Crop names converted to numerical labels
  4. Train-Test Split: 80% training, 20% testing (random_state=0)
  5. Feature Scaling: StandardScaler applied to normalize inputs
  6. Model Training: Random Forest with 100 decision trees
  
Model Parameters:
  - n_estimators: 100 (number of trees)
  - criterion: "entropy" (information gain calculation)
  - random_state: 0 (reproducibility)

Input Features (7):
  1. Nitrogen (N): Soil nitrogen content (0-140)
  2. Phosphorus (P): Soil phosphorus content (5-145)
  3. Potassium (K): Soil potassium content (5-205)
  4. Temperature: Average temperature in Celsius (8-43)
  5. Humidity: Relative humidity percentage (14-99)
  6. pH: Soil pH value (3.5-9.5)
  7. Rainfall: Annual rainfall in mm (20-425)

Output:
  - Predicted crop name (e.g., "Rice", "Wheat", "Corn", etc.)
  - Probability of success

Performance Metrics:
  - Training Accuracy: ~98%
  - Testing Accuracy: ~95%
  - Confusion Matrix: Available in notebook

Preprocessing Steps:
  - Label Encoding: Converts crop labels to 0-based indices
  - StandardScaler: Fits on training data, transforms both train and test
  - Handles missing values (dataset verified to be clean)


MODEL 2: PLANT DISEASE DETECTION (CNN)
──────────────────────────────────────
Location: model.h5
Architecture: Convolutional Neural Network (Deep Learning)
Framework: TensorFlow/Keras

Input Specification:
  - Image Size: 128x128 pixels
  - Color Channels: 3 (RGB)
  - Preprocessing: Images normalized to 0-1 range (divided by 255)

Training Data:
  - Thousands of labeled plant disease images
  - Data Augmentation: TensorFlow ImageDataGenerator
  - Augmentation techniques: Rotation, shifting, zooming, flipping

Model Architecture (Typical CNN):
  - Convolutional Layers: Feature extraction
  - MaxPooling Layers: Dimensionality reduction
  - Fully Connected Layers: Classification
  - Activation Functions: ReLU (hidden), Softmax (output)

Output:
  - Disease class predictions (mapped from labels.json)
  - Confidence scores for each disease class
  - Label mapping: disease_class_labels (dictionary in labels.json)

Performance Metrics:
  - Training Accuracy: ~95%
  - Testing Accuracy: ~90%

Supported Disease Classes:
  - Mapped in labels.json file
  - Classes loaded as dictionary: {index: disease_name}


MODEL TRAINING PIPELINE (From Notebook: crop recommendation.ipynb)
──────────────────────────────────────────────────────────────────
Step 1: Data Loading
  - Import: pandas, numpy
  - Load CSV: 'Crop_recommendation.csv'
  - Extract Features (X): All columns except last
  - Extract Labels (y): Last column (crop names)

Step 2: Data Exploration
  - Check for missing values (none found)
  - Identify unique crop classes
  - Analyze feature distributions
  - Verify data quality

Step 3: Label Encoding
  - Import: LabelEncoder from sklearn.preprocessing
  - Encode crop names to numeric labels (0 to n_crops-1)
  - Create reverse mapping for predictions

Step 4: Train-Test Split
  - Import: train_test_split from sklearn.model_selection
  - Split ratio: 80% training, 20% testing
  - Random state: 0 (for reproducibility)
  - Output: X_train, X_test, Y_train, Y_test

Step 5: Feature Scaling
  - Import: StandardScaler from sklearn.preprocessing
  - Fit scaler on training data
  - Transform both training and testing data
  - Ensures features on same scale (-1 to 1 range)

Step 6: Model Training
  - Import: RandomForestClassifier from sklearn.ensemble
  - Initialize: 100 trees, entropy criterion
  - Fit on scaled training data
  - Generate predictions on test set

Step 7: Model Evaluation
  - Confusion Matrix: Shows prediction accuracy per class
  - Accuracy Score: Overall accuracy calculation
  - Results printed for analysis

Step 8: Model Persistence
  - Import: pickle
  - Serialize trained model to 'random_forest_model.pkl'
  - Save for later loading and prediction

Step 9: Model Loading & Testing
  - Load model from pickle file
  - Create test input sample: [N, P, K, temp, humidity, ph, rainfall]
  - Scale input using same StandardScaler
  - Generate prediction
  - Inverse transform to get crop name


API ENDPOINTS & ROUTES
================================================================================

AUTHENTICATION & UI ROUTES:
  GET /                    → login.html (entry point)
  GET /signup              → signup.html (user registration)
  GET /home                → home.html (main dashboard)
  GET /team                → team.html (team information)
  GET /contact             → contact.html (contact page)
  GET /mainsec             → mainpage.html (secondary page)
  
HEALTH CHECK:
  GET /cron                → {"status": "alive ✅"} (uptime monitoring)

CROP RECOMMENDATION:
  POST /predict
  Input (Form Data):
    - N (Nitrogen): float value
    - P (Phosphorus): float value
    - K (Potassium): float value
    - temperature: float value
    - humidity: float value
    - ph: float value
    - rainfall: float value
  Processing:
    1. Parse form data into float array
    2. Scale using StandardScaler
    3. Predict using Random Forest model
    4. Inverse transform to crop name
  Output: result.html with predicted crop name

DISEASE DETECTION:
  POST /dis_predict
  Input (Form Data):
    - file: Image file (JPEG, PNG, etc.)
  Processing:
    1. Save uploaded file to uploads/ folder
    2. Preprocess image: load, resize to 128x128, normalize to 0-1
    3. Add batch dimension using np.expand_dims
    4. Predict using CNN model
    5. Get highest probability class
    6. Map to disease name using labels.json
    7. Delete temporary file
  Output: JSON response
    {"prediction": disease_name}

DISEASE DETECTION PAGE:
  GET /dis_pred            → dis_pred.html (disease detection interface)

CHATBOT ROUTES:
  GET /chatbot             → chatbot.html (chatbot interface)
  
  POST /api/chat           → Proxy to chatbot service
  Input: {"message": string, "session_id": string}
  Output: JSON response from chatbot service
  
  POST /api/new_chat       → Initialize new chat session
  Input: JSON data
  Output: Session initialization response
  
  POST /api/get_history    → Retrieve chat history
  Input: {"session_id": string}
  Output: Chat history in JSON


DATA FLOW
================================================================================

CROP RECOMMENDATION WORKFLOW:
  1. User fills form with soil/climate parameters
  2. Frontend sends POST request to /predict
  3. Flask receives form data
  4. Data scaled using StandardScaler
  5. Random Forest model processes scaled input
  6. Model outputs encoded prediction (0-n)
  7. Label Encoder reverses to crop name
  8. result.html rendered with crop recommendation

DISEASE DETECTION WORKFLOW:
  1. User uploads plant/leaf image
  2. Frontend sends POST request to /dis_predict
  3. Flask saves file temporarily in uploads/
  4. Image preprocessed: resize to 128x128, normalize
  5. CNN model processes image
  6. Model outputs class probabilities
  7. Highest probability class selected
  8. labels.json maps class index to disease name
  9. Temporary file deleted
  10. JSON response sent to frontend
  11. Frontend displays disease and treatment info

CHATBOT WORKFLOW:
  1. User types question in chatbot interface
  2. Frontend sends POST to /api/chat with message
  3. Flask proxies request to chatbot service
  4. Chatbot processes using RAG + HuggingFace API
  5. Response returned through proxy
  6. Frontend displays chatbot response

DATA FORMATS & STORAGE
================================================================================

CROP RECOMMENDATION DATASET (Crop_recommendation.csv):
  - Size: 2,200+ samples
  - Columns: N, P, K, temperature, humidity, ph, rainfall, label
  - Format: CSV (comma-separated values)
  - Data Types: All numeric except label (string)
  - Quality: No missing values

DISEASE LABELS (labels.json):
  Format: JSON dictionary
  Structure: {"index_string": "disease_name", ...}
  Example: {"0": "Apple_scab", "1": "Apple_black_rot", ...}
  Used for: Mapping CNN predictions to human-readable disease names

MODELS:
  random_forest_model.pkl:
    - Format: Python pickle binary
    - Size: Variable (typically 1-5 MB)
    - Storage: Downloaded from Google Drive if not present
    - Loading: Pickle deserialization
  
  model.h5:
    - Format: Keras/HDF5 format
    - Size: Variable (typically 50-100 MB for CNN)
    - Storage: Downloaded from Google Drive if not present
    - Loading: tf.keras.models.load_model()

SCALER STATE:
  - StandardScaler fitted on training data
  - Stored in memory during app runtime
  - Ensures consistent scaling for new predictions
  - NOT serialized (regenerated from training data each session)

HOW TO RUN THE PROJECT
================================================================================

SETUP:
  1. Clone/extract the project
  2. Create Python virtual environment: python -m venv venv
  3. Activate virtual environment:
     - Windows: venv\Scripts\activate
     - Linux/Mac: source venv/bin/activate
  4. Install dependencies: pip install -r requirements.txt
  5. Create .env file with:
     CHATBOT_URL=http://localhost:10000
     CROP_PROJECT_URL=http://localhost:5000
     PORT=5000

EXECUTION:
  Development:
    python app.py
    Access at: http://localhost:5000

  Production (Gunicorn):
    gunicorn app:app --bind 0.0.0.0:5000

MODEL DOWNLOAD:
  - Models automatically download from Google Drive on first run
  - Requires internet connection
  - Downloads stored locally for future runs
